LLM agents in text games see a key once and need it much later. We extended the FadeMem memory architecture with fact compression, predictive shielding and dormant reactivation, then tested it across 6 memory designs × 3 LLMs. This page replays what the paper found.

2 · Predictive shielding in action

When the agent picks up a key, a rule tags the fact with a trigger: locked.*(chest|door). The fact still fades while the agent explores ten empty rooms. When a locked chest appears, the trigger fires and the fact gets a +0.2 boost, so it stays in the prompt exactly when it's needed.

3 · When does adaptive memory pay off?

Success rate on TreasureHunter across difficulty levels, 30 seeded episodes per bar. Switch models to see the main finding: it depends on the backbone.

CONDITION 1

Long enough episodes

Easy levels finish in 4–8 steps, before the 12-step tagging cycle even runs.

CONDITION 2

Info acquired long before use

On CoinCollector (no key/lock dependencies) shields never fire and there is no gain.

CONDITION 3

A "sweet-spot" backbone

Too weak: it misjudges its own facts and erases them. Too strong: raw history is enough.

CONDITION 4

Basic task competence

On BabyAI, 60–100% loop rates show the bottleneck is spatial reasoning, not memory.
